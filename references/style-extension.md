# 风格延展：体系、场景与提案

> 标志是这套构件最好的一个组合；体系、场景和提案，是同一套构件的其他组合。

这一章写本风格在第 6–8 阶段**看起来是什么样子**。做什么、按什么顺序、查什么，写在共用的 `workflow.md` 和 `deliverables.md`；它们在每个环节都会指到这里。这里写原则、范围和理由，不写具体的颜色值、字体名或物件，具体做法只放进案例。

## 原则：从核心构成关系长出来

几何模块的延展靠**同一套构件**成立：辅助图形、图标、插图、动态、版面网格都从标志的构件表和尺寸单位里来，于是任何一页、任何一个物件，即使不放标志，也能看出是同一家人。最容易走样的地方有两处：一是体系里冒出构件表以外的新形（一张素材插图、一个现成图标），整体立刻散掉；二是阵列铺得太满太匀，变成没有主角的花纹——系统里也要有「稀疏的偏差」，让视线有地方落下。

## 1 体系

| 项 | 本风格怎么做 | 为什么 |
|---|---|---|
| 辅助图形 | 构件按规则排成阵列：序列重复、错位、转向、密度变化；可以铺满，也可以只露一角 | 体系从构件表长出来，铺多大都是同一套 |
| 版式与网格 | 网格的单位等于构件的尺寸单位或它的整数倍；内容按格子落位；疏密适中，信息清楚 | 版面也是一次「组合」，和标志同一种秩序 |
| 字体系统 | 辅助字体选与构件同一种几何气质的无衬线；层级靠字重和大小拉开，少用装饰 | 字不要和构件抢戏，但要同一种构造感 |
| 色彩比例 | 底色占大部分，主色画构件，偏差色只给极少数构件；可以按构件种类分色，但种类要少 | 颜色强化组合规则，而不是另起一套 |
| 图片与插画 | 插画用构件拼；摄影选结构清楚、有重复秩序的画面 | 插画与标志同源；摄影呼应「组合」的气质 |
| 图标 | 用构件拼，与标志同一个尺寸单位和接合方式 | 图标就是更小的组合 |
| 动态的性格 | 构件一件件落位、转向、换位、重新组合；节奏清楚、有拍子；终点帧是标志 | 动态讲的就是「组合」这件事 |

## 2 场景

| 项 | 本风格怎么做 |
|---|---|
| 最能证明本风格的场景 | 构件阵列铺满的大面积场景（官网首屏、展墙、包装）；构件变成实物的场景（可拼的物料、导视单元）；极小尺寸的图标与头像 |
| 材料与工艺 | 偏爱能表现「一件一件」的材料与工艺：分块的面板、可拆装的单元、平涂的印刷、切割与拼装 |
| 场景示意的气质 | 光线均匀、正面或轴测视角、背景干净；示意图本身的构图也按网格落位 |

## 3 提案

| 项 | 本风格怎么做 |
|---|---|
| 版面 | 模块化网格，卡片与图版整齐落位；图与字比例均衡 |
| 字与色 | 延续标志的字与色；编号和标签用等宽或几何字，强调色只做偏差 |
| 叙事的语气 | 清楚、有条理、带一点玩味，像一本做得很好的说明书 |
| 页面节奏 | 「构件页」与「组合页」交替：先拆开讲，再合起来看 |
| 封面 | 标志或一片构件阵列，按网格落位；一眼看出是「拼出来的」 |
| 证据的呈现 | 构件表、尺寸单位、构造图、三种组合的对比、阵列的延展，作为提案的主体证据 |

## 4 规范手册

沿用提案的版面网格；把构件表、尺寸单位、接合方式、角度系统和排列规则写成手册的第一章，后面的每一种应用都回指这一章。

## 延展试金石

交付第 6–8 阶段前，用这几个问题整体看一遍：

1. 遮住标志，看任意一页提案、一个场景、一段动态：还认得出是这个品牌、这个风格吗？
2. 辅助图形能说出它用了构件表里的哪几件、按什么规则排吗？
3. 体系里有没有构件表以外的形？
4. 大面积阵列里，视线有没有地方落下（偏差在哪里）？
5. 版面网格和构件的尺寸单位有关系吗？
6. 和标志并排看，体系里有没有哪一样东西的审美不属于本风格（某个默认模板、某张素材图、某种动效）？

## 案例：EonPoint 方案 A 怎么延展

只借方法，不借形式：这里的具体颜色、字、版式是那个品牌的答案。

| 环节 | 案例里怎么做 | 体现了哪条原则 |
|---|---|---|
| 辅助图形 | 三种构件逐行按同一序列排列、转四分之一圈；约五件里有一件换成强调色 | 构件阵列；稀疏的偏差 |
| 色彩 | 底色、墨色、强调色三种；强调色只给极少数构件 | 颜色强化组合规则 |
| 名片 | 正面标准组合，背面深色满版放大标志 | 构件在大尺度上依然清楚 |
| 官网首屏 | 右侧用构件阵列做主视觉，导航用单行组合 | 阵列铺满的场景 |
| 帆布袋与工牌 | 用阵列的局部做主视觉，标志退到角落 | 遮住标志仍认得出 |
| 提案 | 先讲构件与尺寸单位，再讲组合、配色、系统、场景 | 先拆开讲，再合起来看 |
